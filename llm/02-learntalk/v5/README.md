# LearnTalk v5：兩個 AI 自己創造語法

> v4 的通道是「兩個英文字母」的假密碼，語料本身也帶著語法。
> **v5 把兩者都拿掉**：通道上只有「這個世界的基本概念詞」本身，
> 語料只是一袋袋隨機的詞。於是「一句話長什麼樣」這個問題，
> 沒有任何人給答案 —— 只能由兩位 AI 自己談出來。

---

## 一、v5 到底改了三件事

| | v4 | **v5** |
|---|---|---|
| 通道 | 每個詞 → 兩個英文字母的假密碼 | **直接用原本的中文詞**（沒有假密碼） |
| 語料 | 有語法（主+動+賓、數學式、程式碼） | **零語法**：每行只是一袋隨機抽的概念詞 |
| 語言樣貌 | 人寫死的 | **AI 自己發明**：標記詞、角色標記、結束標記、收件規則 |

`gen_corpus.py` 現在只做一件事：把 256 個基本概念詞（人／鳥／飛／水／火／大／小／零／一…）
依照 Zipf 詞頻**隨機抽籤**，寫成一行一袋的 `corpus.txt`。
裡面沒有主詞、沒有動詞、沒有賓語，也沒有任何標記。

---

## 二、任務：兩位 AI 要把「意義」送過一條沒有分隔符的字詞流

世界給定的只有「意義」：一則訊息由 1~3 個概念組成，每個概念扮演一個語意角色
（施事 / 動作 / 受事 / 工具），整則訊息有句型（陳述 / 疑問）。
**角色集合每則訊息都不同**，所以「位置」不可能代表角色 —— 角色必須被「寫出來」。

通道上只有 256 個概念詞，沒有分隔符、沒有長度標頭、沒有 `⟨END⟩` 這種系統符號。
多則訊息還會被**首尾相接**在同一條流上。

因此兩位 AI 必須自己发明：

1. **功能詞 (function word)**：拿哪個概念詞當「施事標記」「動作標記」…
2. **結束標記**：訊息怎麼收尾？接收端怎麼知道一則訊息結束？
3. **句型標記**：怎麼區分陳述 / 疑問？
4. **收件規則**：接收端怎麼把「標記 → 角色」對應起來。

## 三、數學：兩條 loss 怎麼把這套語法「逼」出來

### 符號

* 詞庫 $\mathcal{V}$，$|\mathcal{V}| = 256$；協定量（AI 自創的語法字典）
  $\boldsymbol{\Theta} \in \mathbb{R}^{(N_{roles}+N_{types}+1)\times|\mathcal{V}|}$
* 一則訊息 $m$：概念集合 $\{w_1,\dots,w_K\}$ 與角色 $\{r_1,\dots,r_K\}$，句型 $t$
* 通道訊息 $M_m = (z_1,\dots,z_{L_m})$，每個 $z_i\in\mathcal{V}$（**沒有分隔符**）

### (1) Listener 的損失：序列標註（讀懂）

Listener 其實在做「**給每個字標註它在這句話裡的身分**」：

$$\mathcal{L}_{\text{lis}}(\phi)
= -\frac{1}{|\mathcal{D}|}\sum_{(M_m,y_m)}\ \frac{1}{|M_m|}
\sum_{i=1}^{|M_m|} \log \hat{p}_\phi(y_{m,i}\mid M_m, i)$$

其中 $y_{m,i}\in\{\text{內容},\ \text{角色標記}\times 4,\ \text{句型標記}\times 2,\ \text{結束}\}$，
是**世界給定的標準答案**（角色是誰、哪個詞是標記、哪裡收尾）。
這一步用交叉熵直接給梯度，是整個系統的「Ground Truth 錨點」。

### (2) Speaker 的損失：REINFORCE + 三個「語法效用」項

Speaker 的每一步動作 $a_t$ 是「下一個詞」；它的對數機率是

$$\log \pi_\theta(a_t \mid \text{scene}, M_{<t}) = \log \frac{\exp \theta_{s(a_t), a_t}}{\sum_{w\in\mathcal{V}}\exp \theta_{s(a_t), w}}$$

（$s(a_t)$ = 這一步對應到協定量的哪一列：角色標記 / 句型標記 / 結束標記）

獎勵由 Listener 的標註結果給出（逐則訊息）：

$$R_m = 0.6\cdot\frac{|\text{真角色集}\cap\text{聽懂的角色集}|}{|\text{真角色集}|}
+ 0.2\cdot \mathbb{1}[\text{句型正確}]
+ 0.2\cdot \mathbb{1}[\text{項目數正確}]$$

$$\mathcal{L}_{\text{spk}}(\theta)
= -\frac{1}{B}\sum_{m=1}^{B}\frac{1}{|M_m|}\sum_t \big(R_m - b_m\big)\log \pi_\theta(a_t|\cdot)
\;+\;\lambda_1\underbrace{\mathcal{H}(\text{協定量})}_{\text{讓一套語法固定下來}}
\;+\;\lambda_2\underbrace{\sum_j \sum_w p_j(w)\,\text{freq}(w)}_{\text{標記詞要冷僻}}
\;+\;\lambda_3\underbrace{\sum_{j<k}\sum_w p_j(w)p_k(w)}_{\text{各槽位不能搶同一個詞}}$$

其中 $b_m$ 是移動平均 baseline，$p_j(w)=\text{softmax}(\Theta_{j})_w$，
$\text{freq}(w)$ 是該詞在語料中的出現頻率。

* $\lambda_2$ 這一項很有意思：**標記詞若太常用，就會跟內容詞撞車**，
  接收端分不清「這是標記還是被標記的內容」→ AI 只好挑冷僻字。
* $\lambda_3$ 保證 7 個標記詞互不重疊。

### (3) 兩階段訓練（語法的「凝固」）

1. **探索期**（前 75%）：抽樣溫度 $\tau$ 由 $1.0$ 退火到 $0.05$，
   語法還在換，Listener 一直追著學。
2. **定型期**（後 25%）：**協定量凍結**，固定用 argmax 那一套語法，
   Listener 針對最終的語法收尾微調。

這一點很重要：真實語言也是「先自由變體、最後凝固成一套標準說法」。

## 四、跑起來

```bash
cd llm/02-learntalk/v5
python gen_corpus.py      # 產生 corpus.txt + lexicon.txt（零語法）

```

（純 CPU 即可，1200 回合約 3 分鐘。`LT_EPISODES` / `LT_BATCH` 可調；

## 五、實測結果

**AI 談妥的語法字典**（每次訓練結果不同，因為是 AI 自己挑的）：

```
句子   ::= ⟨句型標記⟩ ( ⟨角色標記⟩ 概念 )* ⟨結束標記⟩
⟨句型標記⟩ ::= 「左」(陳述) | 「取」(疑問)
⟨施事標記⟩ ::= 「愛」      ← 詞頻第 221/256 名
⟨動作標記⟩ ::= 「少」      ← 詞頻第 236/256 名
⟨受事標記⟩ ::= 「寒」      ← 詞頻第 212/256 名
⟨工具標記⟩ ::= 「軟」      ← 詞頻第 228/256 名
⟨結束標記⟩ ::= 「助」      ← 詞頻第 220/256 名
```

**雙向對話實測**：

```
【第一回合】AI-A 說話，AI-B 聽
  語意：陳述 | 施事=鳥 動作=飛 受事=天
  訊息流： 左〔陳述〕 溫〔受事〕 山 少〔動作〕 飛 明〔施事〕 鳥 助〔結束〕
  AI-B 聽懂了： 陳述 | 受事=山 動作=飛 施事=鳥
```

新概念袋測試：**40/40 完全解讀正確**（角色與句型全對）。

**通道長度穩健度**（一條通道塞多少則訊息還聽得懂）：

| 通道長度 | 10 | 20 | 40 | 60 | 80 |
|---|---|---|---|---|---|
| 正確率 | 100% | 100% | 100% | 90% | 90% |

### 值得注意的發現

* **這是一套「標記型、與語序無關」的語言**：角色完全靠標記詞承載，
  概念先講哪個都聽得懂 —— 因為角色集合每則訊息都不同，位置本來就不可靠。
* **AI 自己學會「標記要冷僻」**：因為常用字會跟內容詞撞車。
  7 個標記詞最後全都落在詞頻第 212~255 名（256 個詞裡最冷僻的那一批）。
* **唯一的弱點**：內容詞剛好就是某個標記詞時（語料中約 3.6% 的句子），
  接收端必然誤判 —— 這是「借用既有詞當功能詞」的固有代價。
* **通道長度有上限**：訓練時通道最多 40 則訊息，超過約 80 則後接收端會開始漏讀
  （90% 左右）—— 真實語言的「一句話能有多長」也是要學出來的。
